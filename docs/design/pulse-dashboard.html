Herdr Pulse

A personal GitHub performance page inside Herdr: PRs, reviews, blockers and code volume across all my gh accounts, with one click to narrow to a single account. Workspaces stay for doing work; Pulse is for seeing where work stands.

1 · Where it lives

Four ways to place a dashboard in Herdr

All four are possible with today's mod system (no core changes). They can be combined; the recommendation is B, with D added later.

A · Tab in a space

Pulse opens as a tab, like Files and Changes

  • Smallest build: tab.new {mod:"pulse"}
  • Can split next to a terminal
  • Belongs to one space, so it feels like part of a project
  • Easy to lose among terminal tabs
B · Own place in the sidebar · recommended

"Pulse" above Spaces swaps the whole main area

  • Top level: not tied to any space or machine
  • Full width for a growing set of widgets
  • Built as a second layout (layouts/pulse.json) that keeps the same sidebar, so switching back is one click and terminals keep running
  • Needs a small sidebar entry in the spaces mod
C · Overlay on a hotkey

⌘⇧P shows Pulse over everything; Esc hides it

  • Fast glance without leaving the terminal
  • Uses the existing overlay API
  • Small; not good for deep lists or charts
D · Sidebar widget

Small "Reviews 3 · Blocked 1" block under Agents

  • Always visible, like the agents list
  • Click opens the full page (B)
  • Only counts, not a dashboard on its own
2 · Moving between screens

A "Screens" entry under Spaces, and Spaces hide while a screen is open

Pulse is the first of many screens. Each variant below shows the sidebar in a workspace and with a screen open. In all of them a screen is a Herdr layout (layouts/pulse.json) opened with layout.switch, so terminals keep running and going back is instant.

V1 · Screens button + list

A "Screens" button under the Spaces list opens a searchable list

  • Exactly one new control in the workspace sidebar
  • Search in the list, so 20+ screens stay manageable
  • Each row can show a live badge (Pulse: 4 need you)
  • Inside a screen the sidebar becomes that screen's own menu: Pulse shows its accounts there, so the account switcher moves out of the top bar
  • Two clicks to reach a screen; add a hotkey per screen for speed

4 · Data

What comes from gh

Accountsgh auth status --json hosts lists every logged-in account; gh auth token -u NAME gives each one's token
My open PRsgh search prs --author=@me --state=open --json …
Needs my reviewgh search prs --review-requested=@me --state=open
Assignedgh search prs --assignee=@me and gh search issues --assignee=@me
Blockedone GraphQL call: reviewDecision = CHANGES_REQUESTED, failing checks, merge conflicts, or a blocked label
Ready to mergeapproved, checks green, mergeable
Lines of codeadditions / deletions of merged PRs in the date range, summed per week
Time to mergemergedAt − createdAt, median

One GraphQL search per account per refresh is enough for everything above. Results are cached in the mod's storage so the page opens instantly, then refreshes every few minutes in the background.

5 · Built to grow

Widgets, not a fixed page

  • Each widget is one file: fetch(accounts, range) → data, render(data) → view.
  • Which widgets show, and in what order, is a list in settings. Turning one off is deleting a line.
  • Every widget gets the same account filter and date range for free.
  • A shared data layer runs the gh calls once; widgets read from it instead of calling gh themselves.

Ideas for later

  • Open in space: click a PR, Herdr opens its repo's space on that branch (Herdr-only feature)
  • Agent time per repo from Herdr's own agent list
  • CI health: flaky checks, slowest workflows
  • Review load: reviews given vs received
  • Streak and activity heatmap
  • Jira / Linear tickets beside their PRs
  • Notifications for new review requests
6 · Before building

Constraints and open questions

  • Herdr mods draw native GPUI, not HTML. This page is only a mockup; the real one is a JS mod using exec("gh", …).
  • exec takes no env vars, so per-account calls go through sh -c 'GH_TOKEN=$(gh auth token -u NAME) gh …'.
  • Charts are drawn with divs (bars), which fits the weekly bar chart.
  1. Rail: should it stay visible in the workspace too (always one click), or can it be collapsed with a hotkey to save width?
  2. What counts as "blocked" for you: changes requested, red CI, conflicts, a label, or all four?
  3. Are all accounts on github.com, or is one on GitHub Enterprise?
  4. Should "All accounts" add numbers up, or show them side by side per account?
  5. Default date range: 7 days, 30 days, or this sprint?
